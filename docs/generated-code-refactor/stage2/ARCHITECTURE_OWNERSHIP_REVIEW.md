# Stage 2 architecture ownership review — evidence-gated P5

Reference baseline: `b8fc52ff41569129959a37487f5417b0fd339527`. Updated after the Stage 2 runtime and fixture checks. This is a **code-consumer review**, not a claim that every possible runtime path has been dynamically exercised.

## Established dependency direction

- **Compilation:** `vg2c.compilation.compile_document` calls parse → classify → resolve → dispatch → emit. `vg2c.emitter.project` loads `vg2c.utilities` compiler handlers, uses `UtilitySpec.operation_definition` and `EmittableOperation.render_method_call`, and records source offsets for existing compiler/editor consumers. These are compiler responsibilities, **not** dependencies of generated `main.py`.
- **Execution:** emitted `main.py` imports `vg2c.runtime`, constructs `JobRuntime`, and calls `job.sql`, `job.html`, filesystem and macro methods. `src/vg2c/runtime/job.py` depends on runtime modules; it does **not** import `compilation`, `emitter`, `semantics`, `workflow`, `editing`, `sql_editor` or `vg2c_ui`. The installed Linux wheel check asserts runtime-only imports and successfully executes a relocated original VG2 fixture.
- **Existing compiler metadata (retain where consumed):** `emitter/models.py` contains `EmittableOperation`, `ParameterDefinition`, `EmittedStep`, invocation offsets and operation definitions. `utility_metadata.py` defines `ValueSchema` and `FileEffectDefinition`; `dataflow/file_effects.py`, `semantics.py` and utility handlers use these. The names do **not** mean a new optional runtime metadata system is present.
- **Optional editor surfaces:** `vg2c_ui/services/document_store.py` imports `vg2c.editing`, `vg2c.workflow`, `vg2c.reorder` and `vg2c.sql_editor`. `editing.py` imports compilation and semantics; `workflow.py` imports editing, semantics and dataflow; `sql_editor/capability.py` imports editing, compilation and semantics. Core compilation does not need to import these editor modules. `sql_editor/parser.py` uses the **shared** `vg2c.sql_lexer`, so deleting the shared lexer as “UI” would be incorrect.

## P5 acceptance gates

1. Every removal has a **zero live core consumer** reference map and explicit regression checks. Dynamic registration/imports must be analyzed, not just textual grep.
2. Every consolidation demonstrates one authoritative algorithm, equal-or-simpler public contracts, and unchanged emitted Python/asset behavior except source-authoritative intentional fixes.
3. Generated `main.py` and installed `vg2c.runtime` import and execute with editor modules absent/unimported. Compiler invocation/source data is **not** a mandatory runtime dependency.
4. Explicitly preserve failures of executable utilities. Do not replace unsupported commands, malformed inputs or service errors with `pass`, broad exception swallowing or a “graceful” runtime fallback.
5. Treat the six longstanding UI/JMP full-suite failures as separately unresolved, not proof that a runtime feature is broken or a reason to delete tests. Stage 2 must report both core and full-suite statuses.

## Deferred future metadata boundary — no implementation in Stage 2

An eventual optional, wheel-shipped description layer may describe publicly supported runtime utility signatures, parameters, defaults, constraints, capabilities and effects for editors. It must import separately; runtime execution must never import, inspect or require it. Compiler-owned invocation/source metadata remains distinct from generic runtime operation descriptions. Missing, stale or malformed descriptions may produce editor diagnostics but can never suppress executable failures or stop `vg2c.runtime` from importing or generating correct outputs. **No new tags, decorators, descriptors, discovery API, registry, manifest, JSON sidecars, metadata-only tests or generated-main changes are authorized or added in this stage.** No choice of introspection versus mappings versus decorators is made.

## Continuation runtime boundary correction: SQL_Get_CSV_List paths

The original source in tests/fixtures/hamizah.txt supplies Windows-style relative paths to SQL_Get_CSV_List, e.g. .\\yeuchuan_a0_5547.tab. The original first four blocks ran with mocked first-two MarsReader results and real downstream SQLite, initially failing with FileNotFoundError on Linux because _CsvIO._read_column treated backslashes as literal POSIX filename characters (red CI 38183108328). The local runtime CSV-list reader now uses PureWindowsPath to convert only relative Windows separators to normalized local path components, resolves under the explicit workdir and rejects UNC/drive-rooted Windows paths. It does not change general job_path, unrelated filesystem APIs, compiler emission, imports, or editor behavior.

This is a **behavioral correctness fix**, not a compatibility shim or extra abstraction: no caller needs to pre-normalize source-written filenames or change original VG2, and the fix is contained in the one authoritative CSV-list input reader. [CI 38183242029](https://github.com/VectorLim/SQLPathFinder_PY_Migration/actions/runs/38183242029) verified 437 green runtime/emitter tests (one warning) including the previously failing four-block fixture, and the unchanged six inherited UI/JMP failures in the 615-pass full suite. The [installed wheel 38183242073](https://github.com/VectorLim/SQLPathFinder_PY_Migration/actions/runs/38183242073) passed. Further user-facing changes to runtime path interpretation would require separate source and consumer evidence.

## Generated Python ownership cleanup — 12 October 2026

The user-facing generated script now imports `job_entrypoint` and defines `@job_entrypoint(__file__) def run(job):` for ordinary scripts. This removes `BASE_DIR`, `WORK_DIR`, explicit workdir resolution and `JobRuntime(...)` construction from generated Python without creating another execution stack. `runtime.job.job_entrypoint` is a normal callable decorator that binds a translated function to isolated project/output roots; it **does not register or describe runtime utilities**. Public `run(workdir=...)` and run-after-relocation behavior remain covered by tests.

Author-supplied embedded Python sometimes uses a literal `workdir` local. Only those projects emit `@job_entrypoint(__file__, with_workdir=True)` and `def run(job, workdir):`; the runtime passes the resolved root. AED config seeding likewise moved into the same runtime entrypoint, which preserves explicit `aed_service_factory` injection. No ambient global job state, mutable singleton, generic runtime metadata, new manifest or compatibility shim was added.

The compiler previously emitted a redundant `header=[...]` or `header=job.table_spec('...header.json')` argument. `emitter.project._table_option`, whose only generator caller was this header path, was **removed**. Query output column naming is normally obtained directly from the SQL result. Explicit original `/HEADERS` can still change casing, select output fields by name or leave unmatched fields blank; therefore the emitter now stores these overrides in a first-line, editable `-- vg2c-output-headers: [...]` SQL comment. `runtime.query.execute_sql` validates and removes the directive before execution, forwarding the equivalent header list to the existing authoritative CSV writer. No new header JSON asset or duplicate SQL output renderer exists.

**Retention decision:** `JobRuntime.table_spec` and `report_spec` are not used by the *new* header emission path but may be called by previously generated translated projects; their mere absence from current emitter calls is not proof of no distributed consumer. Preserve them unless an explicit migration/version compatibility decision authorizes removal. The existing compiler utility metadata and all six inherited UI/JMP failures were left intact.

Red tests were committed first: [workflow 38202171001](https://github.com/VectorLim/SQLPathFinder_PY_Migration/actions/runs/38202171001) recorded five focused expected failures for the old generated setup/header behavior. Following the changes, [workflow 38203059174](https://github.com/VectorLim/SQLPathFinder_PY_Migration/actions/runs/38203059174) passed **445 runtime/emitter tests**, ran the source-preserved multistep original VG2 fixture walkthrough and reported **623 full-suite passes, six inherited UI/JMP failures**. [Linux installed-wheel workflow 38203059146](https://github.com/VectorLim/SQLPathFinder_PY_Migration/actions/runs/38203059146) passed.
