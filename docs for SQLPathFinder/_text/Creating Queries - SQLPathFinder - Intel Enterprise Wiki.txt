will be shown the Add a View or Utility window where you can select one or more views to query. Alternatively, you can
select the open query icon   to load a query you have created or click the open sample queries icon  to choose
some sample queries.

 Toolbar Icons
The SQLPathFinder toolbar displays various icons that allow you to immediately access application functionality. The
meaning of each icon is described in Table 1
Icon Description
  
New Query: Allows you to create a new SQL query
Open Query: Allows you to open an existing query
Open Sample Queries: Allows you to locate and load a sample query
Save Query: Allows you to save a query
  
Run Query: Executes the query
 
Add View or Utility: Opens the Add a View or Utility dialog box allowing you to add another View, Text

Create a Computed Expression: Opens a dialog box that allows you to create an expression for your

configure multiple queries to run consecutively, and allows you to load those jobs to ScriptHost, where
they can be scheduled and run offline.
Show Client Session: Brings the SQL Session window to the forefront of your computer screen.
 
Configure SQLPathFinder: Opens a configuration dialog box where you can set your working directory,
the Excel and JMP executable paths, your query engine, and an Oracle driver.
 
Cancel a Query: Stops a query from executing. Does this by sending a Ctrl+C or Ctrl+Break keyboard
command to the SQLPathFinder SQL window.

The Query Window and Selecting Columns
[Return to Top]
SQLPathFinder views to query and associated columns are shown in the Tree control in the left panel of the Query
window.
Double-clicking Columns in the Tree control adds them to the Columns Grid. There you can rearrange column order and
assign various attributes such as  a column header, a sorting option, a statistical function, a PIVOT option, or whether or
not to display the column. For Sorting, the multi-level Sort order is determined by the top-down order of the Sort
selection.

On the Tree control, icons are used to communicate information about columns.  Keyed columns are indicated using a
Key icon  . Searching by a keyed column generally provides fast access to a table.  Columns that are potentially useful
to include in your report are shown in maroon, and columns to consider filtering on are shown with a blue arrow . A
description for each column you highlight is also shown at the bottom of the Query window. 
 Keyed Columns
Keyed columns generally provide the fastest access to a table. Keys may be gold and open or silver and closed. In the
figure above, note that
lot (c) is a an open-gold key . An open-gold key is the first column in an index and generally provides
fast access to a table. SQLPathFinder generally requires that you include at least one open-gold key in
your filter condition to ensure you get reasonable query performance. The only exception is for views
containing the phrase "status" or "schema" or "master". E.g., WIP_Lot_Status. These views generally
have very few rows or have no keys and do not require the use of a keyed filter by SQLPathFinder.
operation (c) is a closed-silver key . Closed-silver keys denote columns that are part of a multi-column
key in the underlying database table but are not the first column in that key. Searching by a closed-
silver key will not afford performance benefits unless the associated open-gold key is also included in
the filter.
 Blue Arrow Columns
A column that has a blue arrow to its left is an important row filter column that SQLPathFinder suggests you use in your
query to facilitate the data search.  In the figure above, note that column last_entity_occurrence_flag (c), is a blue
arrow column. You should examine the column description for "blue arrow" columns to see if this would be a useful filter
for you. E.g., column Last_Entity_Occurrence_Flag in the Entity_Lot_History view will be set to Y if this is the last
occurrence of the entity for this lot at an operation, and for the date the lot arrived at the operation. It returns N
otherwise. Filtering on this column can avoid duplicate lot-entity associations for an operation pass.

Changing Column Order
[Return to Top]
To change the column order within the Query selection grid, first select the column you wish to move by clicking the
column in the Query Selection grid. Then click the UP or DOWN button to the right of the grid to either move the column
up or down in the order. You may also change column order on the Columns or Filters tab by dragging the column.
[Return to Top]
Deleting Columns
[Return to Top]
To remove one or more columns (i.., grid rows) from the Columns, Filters, of Joins selection grids, highlight the rows,
using the CTRL and the SHIFT keys for multiple row selection, and click the Delete button to remove the rows. To clear
the entire Query selection grid, click the CLEAR button to the right of the Selection Grid.

Sorting Output
[Return to Top]
To order your output, click the cell to the right of the target column under the SORT column in the Columns Grid. You will
be shown a drop down list box with three choices ASC, DESC and None. Select ASC to sort output by the column in
ascending order, DESC to output results in descending order by the column or NONE to disable a sort on this column.
For multi-level sorts , repeat the process for multiple columns. The Sort order will be determined by the Top-DOWN
order of the selected columns.
 
[Return to Top]
 
Choosing Not to Display a Column
[Return to Top]
If you click the cell under the SHOW column of the Query Selection Grid you will see a drop-down list box that allows
you to specify Y to display the column or N or P to not display the column. You may , for example, wish to use a column
in a computed expression but not to print that column in the output. You can use the SHOW option to control whether or
not the column should be included in the report printing. Set to P to have the variable pass through all query levels and
to N to prevent this. Computed columns that span multiple objects must be created in the final query. If you do not wish
to show the intermediate columns, set them to P. You may also specify significant figures for numeric columns. E.g., Y:2
means display to two significant figures

[Return to Top]

Query Output Options node as illustrated below. This sets the Distinct Rows value to Yes. Double-click the option again
to reset the Distinct Rows option and include all rows.

Outer Join
Results
Determines whether a Left or an inner join should be applied throughout the Main Query. For outer
joins, the top table serves as the driving table. For inner joins, only rows that match in all tables are
returned.
Interleave
Results
Allows you to interleave or stack results from Views, Text Files, or Inline Views. Columns with the
same names from different queries will be stacked under each other. Data will also be sorted based
on the sorting applied on the Columns grid. Can be used, for example, to overlay data.
