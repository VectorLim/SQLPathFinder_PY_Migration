Copy Utility - Adding or Moving a CSV File
[Return to Top]
SQLPathFinder allows you to copy files from one area to another prior to or after a query runs. This can be useful to copy a tab or comma delimited file to theSQLPathFinder working directory prior to processing the file, or to copy a result file to a file share after a query completes.
From the Query design form, choose menu option Query -> Add Table or Utility, select Data Area Utilities on the Add a Table window, and double-click the Copy item toadd a Copy Utility to your query. See Figure 1 below. You can position the utility using drag-and-drop.
Double-click the Copy Utility in the Query Design Tree control to configure it. The Utilities - Copy form is invoked which requires a source and destination file. See Figure 2below. If no destination path is specified, the file will be copied to your SQLPathFinder default working directory for both an interactive or a ScriptHost job. Similarly, if nosource path is specified, the file will be copied from your default SQLPathFinder work folder. The Copy Utility also allows you to check option Continue Job if Copy Fails ifyou wish the SQLPathFinder job to contine even if the copy action fails. Click OK to commit your changes and return to the Query Design form.

Microsoft notes that, "all current versions of Microsoft Office were designed, tested, and configured to run as end-user products on a client workstation." "Microsoftalso does not recommend or support server-side Automation of Office." Microsoft further notes that, "a number of complications can occur if Automation takes placefrom server-side code such as .... a Windows NT service." This includes Task Manager. Figure 15 - Including the App=JMP Clause in the Job Queue Name, in order to run a JMP Utility in Batch on Script Host
Debugging JMP scripts can, however, be challenging on ScriptHost. SQLpathfinder does print the JMP log at the end of the JMP utility. Hence, if you add any printstatements, e.g.,
print ("Loaded data and starting analysis ...");
...these print statements will show up in the log to perhaps assist you to determine where a particular issue occurred, if the default error message in the JMP log isotherwise not helpful. As JMP 9 and higher is also multi-threaded, you may need to add a Wait-Utility to wait for the JMP output to be created before moving onto the nextSQLPathFinder Job step if that step is dependent on the JMP output.
Finally, use option "For an Interactive run, leave JMP open after execution" on the JMP utility form with care. This option is intended for use should you already haveJMP open when you run this utility, and you do not want SQLPathFinder to close the previously open JMP session. You could end up with invisible JMP sessions if thisoption is checked and JMP was not previously started. Some people find using the Chart-in-JMP utility a little easier for interactive use.
Optimization Tips on Using JMP:
Processing large files remotely in JMP introduces network and timeout errors. As such:
Make sure you are processing data locally using JMP. I.e., ensure an output file being read into JMP is in the local SQLPathFinder (SPF) work folder and not on a remoteshare (i.e., a share starting with \\). For such cases, no path is specified for the file, e.g., input file may be abc.tab.
Make sure you save the file created by JMP to the local work folder and not to a remote share.  You can always add an SPF Copy utility to copy the journal or JMP or CSVfile created by JMP to its final destination after the JMP utility runs. As JMP often releases control, continues on in the background, and goes on to the next step beforeJMP has completed a particular step, you will need to add an SPF Wait-File utility after the JMP utility to wait until the JMP Journal or other file is created before the Copyutility runs, otherwise the copy utility may not find the file to copy.
When loading data to JMP, specify column data types versus letting JMP decide on default datatypes. This can significantly speed up the load of the file to JMP. Ifdatatypes are not specified, JMP reads the input file twice, once to determine datatypes and then to load the data.
E.g., of inclusion of datatypes in a JMP load is as follows:
Open( "abc.tab",    columns( DEFECT_ID = Numeric,                INSPECT_EQUIP_ID = Character,                INSPECTION_DATE = Numeric,                KEYSORT = Character,                LOT_ID = Character ),

Introduction
With reduced quotas being implemented on the MARS/ARIES/OASys (MAO) database servers, it is important to write our queries efficiently to avoid exceed quota errorsand long running jobs.  One way to do this is by generating incremental extracts. That is, instead of extracting 60 days of data every day, build up a 60 data extract file anduse SQLPathFinder's incremental capability to append new data since the last time the job ran, to update changed data, and to roll off data that is older than 60 days. Much of this can be achieved using SQLPathFinder's GET-SITE-TIME and SMART-APPEND utilities as illustrated in Figure Inc-1 below
Figure Inc-1 - Utilities for an Incremental Extract
The Get-Site-Time utility obtains the current time at a site, the Main Query pulls incremental data since the last time the job ran, and the Smart-Append utility appends,updates, and deletes data in an old file based on criteria set and data extracted from the main query. If successfully run, the Smart-Append utility also updates a time filewith the time retrieved by the last Get-Site-Time utility. That time file is also used in the Main Query of the next query run so that data pulled is greater than or equal to thelast successful site extract Time. This process should greatly reduce the time taken to run your daily job.
The process is summarized in Figure Inc-2. In Step 5 below, the Old file is copied to the work folder if it is on a file share and processed together with the new file. Resultsare saved back to the Old file which is then re-copied to its original folder. If everything is successful, the SMART-Append utility will, if configured thus, update the lastsuccessful extract time to an Update file used by the Main Query (step 7 in Figure Inc-2)..

Creating the Initial Large Extract File

The second query processes those lots or items so many items at a time. In addition, for the first query run, you would not need to use theextract time file but can simply specify a date range. Notes on the Site-Loop Utility
[Return to Top]
The Site-Loop utility allows you to efficiently loop through a list of database nodes. Site-Loop also allows a job to continue even if one of the site-queries fails. The affectedloop iteration would end on the query failure, and the job will resume at the beginning of the next Site-Loop iteration.  Any Update-Time actions within the Site-Loop(whether part of the Smart-Append or Update-Time utility) will not happen, so that the next time the job runs, it will try again to pull the data that it failed to pull this time, andwill continue to do so until that site is finally successful. Below is an example of the new behavior.
A sample query is shown in Figure SL-1. The query deletes an output file, uses Site-Loop to loop through a join query using a list of nodes and, as part of the Site-Loop, executes  a pre/post query,  runs a few utilities, and leverages a Smart-Append utility to union the query results into a single output file. At this time, Site-Loop will only behave this way with failed intermediate queries and not with utilities as wedid not want to risk potential corruption of any data set due to unintended consequences. A severe failure with a utility (e.g., Smart-Append) will still result in the entire jobaborting.

If-Then-Else Utility
[Return to Top]
The If-Then-Else utility allows you to conditionally execute steps depending on a condition evaluating to TRUE or FALSE. E.g., a user may choose to email a group ofusers if a notification query returns 1 or more rows. The ELSE option allows execution of a sequence of steps if the If-Then-Else utility translates to FALSE. Stepsassociated with an If-Then-Else utility will be indented underneath the utility for ease of readability. This is illustrated in Figure if-1. 
The If-Then-Else utility optionally supports two AND/OR conditions. This is illustrated in Figure if-2. In Figure 2, two conditions are connected using an AND clause,meaning both conditions must be TRUE. If an OR clause were used, then either condition must be true for the If-Then utility to translate to true. You will be able to useEnvironment Variables, Global Variables, command-line variables as well as constants in the variable portion of an IF-Then utility test. To use Global, Command-line orMacro variables,  surround the variable with VAR(). This is illustrated in Figure if-2. In Figure if-2, command-line variable cl_user (i.e., VAR(<<<cl_user>>>) ) is compared tovalue jmclarke. A command-line variable is a variable passed to the SQLPathFinder executable. Command line variables start with “cl_”.
Note that if an IF/THEN condition cannot be evaluated due to a data type mismatch (e.g., comparing two strings using the EQ operator rather than an EQS operator), theSQLPathFinder extract engine will abort the job.

Mongo-Import Utility
[Return to Top]
The Mongo Import utility imports a CSV or a JSON file into a Mongodb database. Rows can be inserted (Import Mode= Insert) or updated (Import Mode = Upsert) based onyour identified key columns (opt. Upsert Field(s)), otherwise an _id column will be assumed to be the primary key. You can also insert/update fields into rows of an existingMongodb database collection (i.e., Import Mode=Merge).
Field Options are:
Input Option Description
Connection This is the connection to the Mongo Database. This is an @ delimited string of format: server:port@database@@username@password. E.g.,atdspwidelrds1:27017@ATM_KS@@un@pw
Input File  This is the path and name of the CSV/TAB or JSON file to import. The file extension determines the type of data to be imported. A comma delimitedfile should have an extension of .csv, a tab delimited file should have an extension of .tab, and a json file should have an extension of .json.
Collection This is the name of the MongoDB Collection to insert data to.
Number ofWorkers lets you specify multiple parallel threads for the import to speed data loading
Import Mode Controls whether you wish to insert rows, update rows or merge rows. Valid values are:
insert: Insert the documents in the import file. mongoimport will log an error if you attempt to import a document that contains a duplicate value fora field with a unique index, such as _id.upsert: Replace existing documents in the database with matching documents from the import file. mongoimport will insert all other documents.merge: Merge existing documents (i.e., insert or update fields in a matching document) that match a document in the import file with the newdocument.
opt. UpsertFields Modifies the import process to update existing objects in the database if they match based on the specified field list.
OtherArguments For Other arguments, option --ignoreBlanks is common to not load a field if it stores an empty string. In addition, for CSV/TAB file imports, option --columnsHaveTypes lets you include field data types as part of field column headers. Otherwise Mongo will try and assume the datatype of the fieldbased on actual data.
An example of column headers with datatypes used with option --columnsHaveTypes are as follows:
_id.string(),lot.string(),operation.string(),retest.int32(),tool.string(),timestamp.date_oracle(yyyy-mm-ddhh24:mi:ss),tool_group_code.string(),bga_no.int32(),visual_id.string()

Config.ini file
This is the config file that allows the user to configure the look of the report and charts.  The configuration file can be as simple as a single header with a single value to bechanged or as complex as the sample config.ini file in the link below.  Even if the sample config.ini file contains all options, the best practice is to leave only the optionsthat need to me modified and delete any other option that you want to leave as default.
The config.ini file has multiple sections, Report Configuration, Correlation plot configuration, General Chart Configuration, Carrier Map Configuration and Wafer MapConfiguration.
Below some of the options are described, the most self intuitive ones are not explained.
A config.ini file with most options available can be found here → Link.
